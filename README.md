# pipe2p

pipe2p is a secure, peer-to-peer data transfer utility built on [libp2p](https://libp2p.io/).
It allows you to easily share files or pipe data streams between devices across the internet, 
seamlessly handling NAT traversal (hole punching) and falling back to relay servers when a direct connection cannot be established.

## Features

* **Peer-to-Peer:** Direct connections via libp2p hole punching whenever possible.
* **Secure by Default:** All data is transferred using end-to-end encrypted connections.
* **Seamless NAT Traversal:** Automatically falls back to circuit relays if direct connections fail.
* **Piping Support:** Stream data directly via `stdin` and `stdout`. Perfect for sharing logs, databases, or terminal output.
* **Built-in Compression:** Optional `zstd` compression to speed up transfers of compressible data.
* **Custom Relays:** Use the public libp2p network or self-host your own dedicated relay.

## Usage

### Transferring a file
To send a file, simply pass the file path to the `send` command. This will generate a unique peer code.

```bash
pipe2p send hello.txt
```

On the receiving machine, use the `receive` command along with the code generated by the sender.

```bash
pipe2p receive <peer-code>
```

### Piping data (stdin / stdout)
pipe2p handles standard input and output like a traditional unix pipe.
If you don't specify a file, it will read from `stdin` and write to `stdout`.

**Sender:**
```bash
tar czf - ./my_folder | pipe2p send
```

**Receiver:**
```bash
pipe2p receive <peer-code> | tar xzf -
```

### Compression
You can compress the data stream on the fly using `zstd` by passing the `-c` (or `--compress`) flag.
You can also specify the compression level with `-l`.

```bash
pipe2p send -c -l 16 large_dataset.csv
```

## Global Flags & Options

* `-v`, `--verbose`: Enable verbose output for debugging connections.
* `--relay <multiaddr>`: Use a custom relay node multiaddress instead of the default bootstrap peers.

## Releases

This repository is configured for [GoReleaser](https://goreleaser.com/) with `.goreleaser.yml`.
Builds inject the CLI `version` via linker flags:

* Snapshot/dev builds use the short commit hash.
* Release builds use the semantic version tag.

**Note:** Public bootstrap nodes have very strict limits, so if hole punching fails, they generally won't suffice for heavy transfers.

## Hosting Your Own Relay

While pipe2p uses public libp2p bootstrap nodes by default, you can host your own relay for better performance, privacy, or firewall circumvention.
The included relay currently exclusively supports websocket connections because they offer the best firewall/proxy circumvention.

It can be found in `cmd/relay`.

### Running the Relay
By default, the relay binds locally to `http://[::1]:4001`.
To expose it to the internet securely, you will need to set up a reverse proxy (such as Nginx, Caddy, or Traefik) 
to handle TLS termination and forward external traffic to this local port.

```bash
go run ./cmd/relay -domain relay.yourdomain.com -port 4001
```

* `-domain`: **(Required)** The public domain name pointing to your relay for WSS (WebSocket Secure) connections.
* `-port`: The local port to listen on.
* `-keyfile`: Path to store/load the node's private identity key. (Default: `relay.key`)

Once started, the relay will output its WSS multiaddress. You can then use your relay with the CLI:

```bash
pipe2p send --relay /dns/relay.yourdomain.com/tcp/443/wss/p2p/<relay-peer-id> my_file.txt
```
